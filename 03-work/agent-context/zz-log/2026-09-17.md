## OpenRouter Sol and Opus delegation fallback

- Added `sol-or-worker` and `opus-or-worker` to the `glmxm` session-scoped worker set so a GLM top-level orchestrator can delegate bounded work through prepaid OpenRouter credit when the Codex and Anthropic subscription pools are exhausted. The aliases are deliberately distinct from subscription-backed `sol-worker` and `opus-worker`, both set effort to `high`, neither is selected automatically, and the existing server-side key limit remains the hard spend boundary.
- Added OpenRouter provider mappings for `openai/gpt-5.6-sol` as `sol-or-high` and `anthropic/claude-opus-5` as `opus-or-high`; refreshed the installed provider, guard policy, and helper commands, then restarted the owned CLIProxyAPI service.
- Corrected `openrouter-smoke` so its tool request no longer conflicts with the plain-response system prompt and now forces the declared echo tool. Live billed verification passed for both aliases through the Anthropic wire: each returned HTTP 200 for plain text and an Anthropic-format `tool_use` for the forced tool request. Combined final smoke cost was approximately $0.0041.
- Verification passed: 48 CLIProxy launcher tests, 185 agent-guard tests, 35 launcher model-lock tests, 19 OpenRouter manifest tests, 14 smoke-payload tests, shell syntax, and scoped whitespace checks.

## Primary/fallback Codex OAuth routing

- Added a second Codex OAuth credential to the live CLIProxyAPI auth directory. The pre-existing larger subscription is priority `100`; the newly added smaller subscription is priority `10`.
- Configured `routing.strategy: fill-first` so Codex-backed launchers and workers consume the larger account first and automatically fail over when it becomes unavailable. Enabled one-hour session affinity with subagent inheritance to keep a conversation and its children on one upstream account where possible.
- Created private timestamped backups of both credential files and the proxy config before modification. The loopback management API then reported two active Codex credentials with the expected priorities and the provider ready. No launcher, model alias, or agent-guard change was required because both accounts serve the existing Codex model routes.

## Claude Code 2.1.251 worker-precedence compatibility

- Diagnosed three built-in `Explore` workers from a Sol-locked `claudex` session routing to Claude Opus 5. Claude Code 2.1.251 changed `CLAUDE_CODE_SUBAGENT_MODEL` from an override to a lower-priority default, so the built-in agent definition escaped the launcher pin while the guard—seeing no explicit model in the Agent payload—incorrectly assumed the lock controlled the runtime route.
- Updated every pinned launcher to set `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` and every flexible launcher to clear it. Updated `agent-guard` to fail closed on any locked Agent or Workflow call when the force marker is absent, giving already-running stale sessions an actionable restart error instead of allowing a cross-lane request.
- Upgraded the installed Claude Code from 2.1.251 to 2.1.276, published the repaired guard and global policy, and verified a synthetic call from the stale Obsidian session is denied before reservation. Verification passed: 35 launcher model-lock tests, 51 CLIProxy launcher tests, 186 agent-guard tests, 15 delegation-policy tests, shell syntax, frontmatter validation, and scoped whitespace checks.
