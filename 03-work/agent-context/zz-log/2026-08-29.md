## Delegation Flight Recorder

- A multi-worker session exposed a recovery gap: task state and parent transcripts did not provide a compact, reliable account of findings from workers that could disappear with a terminal, VM, or host failure.
- Added the Delegation Flight Recorder pattern: one private run per genuine user prompt, one human-readable journal per native worker, an append-only event ledger, semantic checkpoint commands, startup recovery, and explicit close/abandon receipts.
- Chose lifecycle hooks rather than extending Agent prompt parsing in `agent-guard`. `SubagentStart` and `SubagentStop` provide actual worker identity; `PostToolUse` and `PostToolUseFailure` provide bounded incremental activity; the existing guard remains solely responsible for model, fan-out, and Workflow admission.
- Automatic records intentionally omit Write/Edit bodies, raw tool output, environment dumps, and full Agent prompts. Common secret assignments and authorization values are redacted; state is machine-local with private modes, locks, fsync, and atomic manifest replacement.
- Completion does not delete evidence automatically. The orchestrator closes a run only after synthesis and verification reach a durable destination; closure writes a minimal receipt and removes transient worker detail. Interrupted work is recovered rather than blindly redispatched.
- Extended the global guard installer to own the recorder scripts and lifecycle hooks idempotently while preserving unrelated settings and the existing Bash-safety installation work.
- Added focused synthetic coverage for concurrency, corruption, redaction, lifecycle transitions, recovery, closure, abandonment, and installer idempotency.
- Installed the verified scripts and hooks globally through the idempotent guard installer. No services or project sessions were restarted.
- Fresh-session direct-Agent witness: one Explore worker received the injected contract, produced two semantic checkpoints and three automatic tool events, returned its final message, and left a recoverable 1/1-terminal run; explicit close wrote a minimal receipt and removed transient detail.
- Fresh-session Workflow witness: the registered one-phase `bounded-parallel` harness ran two independent workers, each received a separate journal and wrote two checkpoints; the parent observed 2/2 terminal and closed the run with only a receipt remaining. This harness matched the smoke test's exact one-parallel-phase shape, so no dynamic-workflow substitution or approval bypass occurred.
- Fresh-session interruption witness: a synthetic 0/1-terminal run was surfaced by `SessionStart` with its exact run ID, then explicitly abandoned after verification.
- Immediate dogfooding exposed one false-positive path: `TaskCompleted` created a new empty run even when no delegation existed. Changed it to associate only with an already-open prompt run, added a no-delegation regression, reinstalled the fix, and abandoned only the empty test artifact. Recorder runs belonging to other active sessions were left untouched.
