## Sandboxed computer-use profile

- Promoted the single-file lifecycle tool, both derived-image recipes and their sources, and both deterministic test suites to [`profiles/cu-sandbox/`](../../../profiles/cu-sandbox/). Integration results and the trial's extracted upstream MCP source remain outside the repository: the pinned guest already supplies that module, while the CLI embeds only the exact-five-tool narrowing bootstrap.
- Separated writable state/share defaults from immutable build sources. `--root` / `CU_SANDBOX_ROOT` stays available; its default now resolves under runtime `$XDG_STATE_HOME` or `~/.local/state/cu-sandbox`. Image sources resolve relative to the installed script, independently of working directory and state-root overrides. Existing explicit flags and environment overrides remain supported.
- Default container/network names are `cu-sandbox` / `cu-sandbox-internal`. The old `cu-sandbox-trial` container is not migrated or changed. The immutable-container-ID MCP startup gate and interrupt-safe startup cleanup remain intact.
- Retained the exact local base-image pin and documented the corresponding upstream registry digest for separately authorized provisioning. Both recipes still build offline; no pull, build, start, reset, or removal was performed during promotion.
- Kept the boundary explicit: Claude Code is the only agent loop; MCP exposes exactly five model-free tools; configuration is per-run and older output must be regenerated. The guest-session permission kind remains unimplemented, so the reusable profile is still trial-grade, not a governed path.
- `bun run check:frontmatter` passed (235 files); the final tracked diff passes `git diff --check`. Offline discovery passed **46 tests: 34 CLI contract/portability tests and 12 accessibility reader/session tests**. Read-only help/status smoke passed; the retained trial container reports `exited`. The profile leak scan found only four permitted guest-internal `/home/kasm-user` references and no host-specific identifiers.

## Guest-session permission draft and profile smoke

- Live smoke of the promoted `cu-sandbox` profile from a clean worktree: verify passed 22/22 (23/23 on the accessibility image), before and after `reset`, and the five-tool MCP smoke returned a screenshot and an accessibility tree. Containers were left stopped.
- The smoke found two packaging defects, both fixed: the CLI lost its executable bit (the repo sets `core.fileMode=false`, so the bit must be recorded with `git update-index --chmod=+x`), and under umask 077 the guest could not read the share because rootless guest UIDs do not map to the host owner. `up` now refuses a share without world read and execute bits before any image, network or container call, and the README adds the `chmod 0755` step. 47 offline tests pass.
- Drafted [Guest-session permission kind](../../../02-stack/01-ai-coding/guest-session-permission-kind.md) (`status: draft`). Decision: a separate `guest_session` kind bound to the exact running container, enforced per call by a persistent host stdio mediator that replaces the final `os.execvp` in `mcp-launch` (today the gate checks only at startup). Release prerequisites: an authenticated root-session transport, the mediator, and container/attestation drift checks. No permission-core or desktop-bridge code changed.
- Delegation lessons: one Sol worker reading the whole permission core and both consumers failed with "Prompt is too long"; splitting into two scouts plus an explicit context budget (grep, then `sed -n` ranges) fixed it. Sol workers declined to write scratch notes `.md` files, so the scouts' structured returns were passed to the drafter instead. Every role, including the adversarial review, ran on Sol 6.1 at the user's request; the review returned no findings, but it is same-family review, so an independent non-Sol pass is still worth doing before implementation.

## Governed steward (scheduled agent work) design

- Gap named by the user: the scaffold governs interactive delegation but has no governed form of unattended or scheduled work. Their concerns are runaway cost, hardware use, overreach (subsidiarity) and alignment drift across limited context.
- Essence-first design in `zz-research/2026-10-02-governed-steward.md`: Charter / Run / Envelope / Inbox / Ledger, a subsidiarity ladder (deterministic, then cheap capped model, then subscription model, then human), and every limit enforced outside the model (systemd slice limits, `--max-budget-usd`, expiring hash-pinned charters, proposals instead of actions).
- Proposed first slice is model-free: a nightly health report under a systemd envelope. Nothing is installed yet.
- Implemented [`profiles/steward/`](../../../profiles/steward/README.md): stdlib level-0 CLI, exact-byte expiring charter pins, private state, serialized daily accounting, collected systemd resource envelopes, one JSONL ledger entry and inbox note per attempt, and a read-only health charter. The human chose **start simple**: commit a reviewed charter and run installation by hand; no permission-controller integration, model execution or automatic renewal.
- Deterministic suite passed **54 tests**. Live scratch-only smoke: health `ok`; edited-copy pin `refused`; three-second runtime ceiling `stopped` (`timeout`); 32 MiB allocation envelope `stopped` (`oom-kill`); PrivateNetwork `enforced`; daily cap `skipped`. Fresh final-code verification produced six ledger lines and six notes for six attempts; the earlier eight-attempt diagnostic history (including two initial skips/refusals) was retained separately. All steward transient units collected, generated units passed systemd syntax verification, and the persistent user-unit directory stayed unchanged.
- Smoke corrected two integration defects: peripheral Device-scope batteries must not count as system batteries, and a scrubbed controller still needs a derived user-manager runtime-directory hint while its charter child remains environment-clean. Podman cannot join its existing rootless namespace inside PrivateNetwork, so its read-only query is honestly reported unavailable; no container remediation was attempted. Filesystem isolation and dependency pinning are explicitly not claimed.
- Review hardening closed four defects: manager environment expansion is explicitly disabled before `env -i`; pins bind the resolved charter path as well as its bytes; deeply nested TOML yields one audited refusal instead of an uncaught parser recursion error; calendar values are passed after an option terminator. Explicit manager `exit-code` evidence also overrides numeric 137/143 kill heuristics. Five regression methods bring the passing deterministic suite to **59 tests**.
- Post-fix smoke reran only health and runtime cases using the same scratch state/inbox/unit directories and 300-second command timeouts: health `ok` (2.047 seconds), three-second runtime envelope `stopped: timeout` (3.828 seconds), PrivateNetwork `enforced` in both. Exactly two ledger rows and two inbox notes were added; no steward transient units survived, and persistent user-unit files stayed unchanged. No timer was enabled, no model ran, and no commit or push occurred.

## Per-call mediator in cu-sandbox

- `cu-sandbox mcp-launch` no longer execs into the guest MCP server. A persistent host stdio mediator now sits between agent and guest: strict JSON-RPC framing, a five-tool allowlist with strict per-tool argument schemas, an exact-ID `podman inspect` drift check before and after every call (results withheld on drift; failures close), forwarding only responses whose IDs it sent, a filtered `tools/list`, and serialized calls.
- Grant seam: the default gate is still an **ungoverned trial** and says so on stderr. `--require-grant` / `CU_SANDBOX_REQUIRE_GRANT=1` refuses every call, naming the unimplemented `guest_session` kind. No grant lookup exists yet.
- All-Sol build → adversarial review → fix → recheck. The review found two medium defects, both fixed with regression tests: signals swallowed by the selector loop, and request IDs becoming response-eligible before their frame was fully written under backpressure. The suite has 80 tests. The live smoke passed before the fixes; the fixes are unit-tested only.
- Lesson: a killed live-smoke bash call left the sandbox container running (the drift phase got as far as `up` and never reached teardown). The orphan was found afterwards and stopped. Smoke scripts should tear down in a `finally`/trap, and every run should end with a status check.
- Still open: `guest_session` enforcement in the permission core, an authenticated session transport, and a cross-family review (this review used Sol only).

- Added `cu-sandbox session`: one command owns one guest desktop for one agent lifetime. It takes a canonical per-UID/container-name lock (independent of `--root`), starts or fully verifies the container, writes a private per-run MCP config, launches the agent unchanged (never picks a model or lane) in its own process group, and on exit or SIGINT/SIGTERM/SIGHUP tears down the whole group, deletes the config and stops the container. SIGKILL/host crash still needs `down`.
- Sol review found three medium/high lifecycle bugs (signal at finalizer entry skipped teardown; signal before the Popen handle was assigned orphaned the agent; `--root`-keyed lock let two sessions share one desktop); I added a fourth (shell-wrapper descendants survived). All fixed with real model-free regressions; suite 105 tests. Live model-free smoke passed all five cases before the fixes and cases (a)/(d) after; container ended **exited**.
- Leaf-rule lesson: Sol workers loaded skills despite instructions, a skill spawned a background reviewer, `SendMessage` to that stopped agent resumed it, and the fix worker twice blamed an "unidentified writer" for its own edits (disproved from its transcript). Prompt-level leaf rules are not enough; skills and peer messaging need deterministic blocking for workers.
