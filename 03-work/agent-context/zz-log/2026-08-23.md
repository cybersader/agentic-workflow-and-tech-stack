## Portagenty feature documentation

- Reframed the docs homepage around six outcome-oriented capability families instead of extending an increasingly stale feature-card inventory.
- Added a dedicated top-level Features page for the comprehensive shipped surface: workspace organization, persistent sessions, cross-device use, navigation/scaffolding, management/export/integrations, and **experimental Linux resource supervision**.
- Kept the platform-specific capability integrated rather than calling it an extension: Portagenty remains portable, while the systemd-user/cgroup-v2 supervision backend is capability-aware and Linux-specific.
- Made the supervision boundaries explicit: soft guardrails, exact ownership proof, ordinary-session non-adoption, fail-closed ambiguity, and no Portagenty daemon, listener, history store, or unattended telemetry.
- Added the Features route to Starlight navigation and smoke coverage; the static build and all 12 route checks passed.

## Supervised workspace live-state fix

- Fixed the top-level picker count path, which only matched ordinary workspace-scoped multiplexer names and therefore omitted supervised sessions whose exact targets are intentionally private and opaque.
- Picker counts now union ordinary live targets with supervision receipts that pass exact backend reconciliation. Stale, unreadable, unsupported, or otherwise unverified receipts still cannot make a row look live, and an ordinary/owned overlap counts only once.
- Added picker regression coverage for ordinary + owned union/deduplication, cross-workspace receipt isolation, and legacy workspaces without stable IDs. Picker tests and Linux clippy with warnings denied passed.

## Fable cross-provider flexible launcher

- Added `fablexm`: a contained Fable 5 orchestrator routed through loopback CLIProxyAPI with both Claude and Codex providers preflighted. It complements rather than replaces native-Anthropic `fablem` and pinned-Sol-worker `fablex`.
- The implementation deliberately uses `gpt-5.6-sol` as the **unlocked default** worker model. A Fable-main Agent tool cannot explicitly name the foreign Sol model through its Claude-only override enum, while explicit Claude worker models and agent frontmatter can override the default when `AGENT_GUARD_SUBAGENT_MODEL_LOCK` is absent.
- The quota boundary is now explicit in launcher copy and global policy: Fable orchestration and Claude workers spend the Anthropic five-hour pool; Sol workers spend the weekly Codex pool. Mixed fan-out must disclose its model mix, and routing/authentication/quota failures stop rather than retry-loop.
- Added `fablexmy` and `fablexmry` only; no automatic `u` alias. Updated the interactive `x` picker and `cc-handoff` launcher allowlist so `fablexm` is selectable and recoverable as a named lane.
- Corrected an adjacent containment gap in `fablem`: `env ... claude` bypassed the shell wrapper, so the function now calls `claude-contained` directly.
- Added hermetic provider-gate, environment, argument-forwarding, lock-policy, menu, handoff, alias, and containment regression coverage.
- Final validation passed: shell syntax; 17 CLIProxy launcher tests; 14 launcher/model-lock tests; 44 agent-guard tests; 4 installer tests; 12 bash-guard tests; isolated function/alias checks; both read-only provider health checks; and `git diff --check`. Containment reported all three Claude roots contained and every policy check passing, with an unrelated warning for 20 stale rollback receipts.
