## Opus cross-provider launcher

- Added `opusxm`: Opus 5 `[1m]` orchestrates through CLIProxyAPI while both
  `CLAUDE_CODE_SUBAGENT_MODEL` and `AGENT_GUARD_SUBAGENT_MODEL_LOCK` are unset.
  Model-neutral workers therefore inherit Opus and explicit Claude model choices follow
  normal Claude Code resolution.
- Added a session-scoped `sol-worker` through Claude Code's additive `--agents` option.
  Its full model ID is `gpt-5.6-sol`, its prompt makes it a terminal leaf, and its
  description calls out the weekly Codex meter. This provides an explicit foreign-model
  route without turning Sol into a higher-precedence environment default.
- Kept the main inside `claude-contained`, preflighted both Claude and Codex OAuth
  providers, retained the Opus 1M context, and intentionally omitted the Sol-only
  compaction settings. Added the `y` and `ry` aliases plus `x`/`ccx` and `cc-handoff`
  discovery surfaces; no automatic ultracode opener was added.

## Model-resolution correction

- Current Claude Code documentation defines subagent model precedence as environment
  default, per-invocation model, agent definition, then main model. This disproved nearby
  prose that treated `CLAUDE_CODE_SUBAGENT_MODEL` as an unlocked default that explicit
  models could override.
- Corrected the canonical global policy and launcher documentation. Pinned lanes still use
  both layers for different reasons: the environment selects Claude Code's route and
  `AGENT_GUARD_SUBAGENT_MODEL_LOCK` independently enforces the declared route at admission.
- Left `fablexm` behavior unchanged but documented its present limitation: because it still
  sets Sol in the highest-precedence environment variable, current delegated workers resolve
  to Sol even though the guard model lock is absent. A future Fable-lane redesign remains a
  separate task.
