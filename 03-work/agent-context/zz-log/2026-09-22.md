## Opus 5.5 proxy identity fix

- A real `opus55xm` Opus 5.5 subagent failed with `400 Claude Code 2.1.258 does not support this model; version 2.1.280 or newer is required`. Local Claude Code, the parent session, and the transcript were all 2.1.280. The proxy error logs showed the cause: CLIProxyAPI replaced incoming `User-Agent: claude-cli/2.1.280` with its pinned 2.1.258 fingerprint and rewrote `cc_version=2.1.280.d95` to `2.1.258.a65`. The catalog patch had proved only `/v1/models`, not the production route.
- Added `profiles/cliproxy-opus55/patches/0002-claude-code-2-1-280-identity.patch`. It moves the baseline identity to 2.1.280 and derives the system-instruction version from the same baseline. The SDK/runtime tuple (0.112.1 / v26.3.0) already matched what 2.1.280 sends. The unchanged billing-hash algorithm reproduced all four native 2.1.280 captures (`d95` and `afa`), and one synthetic fixture reproduces `d95`. Upstream 2.1.258 test fixtures moved to 2.1.280, and new tests cover preserving a native client, rewriting an older client, and the billing header.
- The build now runs `go test ./internal/registry ./internal/runtime/executor/...` (all pass) and records `claudeCodeIdentity: 2.1.280`. Two builds were byte-identical: SHA-256 `ad6aa55747eaaa42dfc2d2d1daf69863b97dcd82087f52581200af28316e83d6`. `verify-candidate.sh` confirmed the exact model on the isolated port without inference.
- Added `_cliproxy_require_opus55_identity` to `opus55x`, `opus55xm`, and the `ccx` proxy brain path. It requires the running binary's SHA-256 to match an active receipt recording the 2.1.280 identity, so an older catalog-only proxy fails closed instead of opening a session that 400s. The installer refuses receipts without that identity.

## ccx live-session guard

- Cause: resuming an exact UUID that Claude Code already runs as a background session made Claude refuse the launch. Claude's daemon had also restarted that background session with only `--resume --model --permission-mode`. Without the launcher's `--agents` JSON, `claude attach` would drop `sol-worker`, `sonnet-worker`, and `astra-worker`. Environment variables were preserved; only the worker definitions were lost.
- Added `_claude_live_session` (read-only `claude agents --json`, about 0.13s). ccx now checks plain exact-UUID resumes before launch. A background match offers these choices: stop and resume under the launcher (default; polls until the session exits and fails closed if it never does), fork under the launcher, attach as-is with the reduced worker set, or cancel. A match open in another terminal offers only fork or cancel, and the other process is never signalled. A dry run reports the action without taking it. If the check cannot run, ccx notes this and resumes as before. Direct lane calls such as `opus55xm -r` are not covered.
- A Sol worker implemented the change against a fixed contract, and the orchestrator reviewed it. Tests pass: 52 launcher model-lock (10 new), 65 CLIProxyAPI launcher, and 3 cross-provider wrapper tests.
