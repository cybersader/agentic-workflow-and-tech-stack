## Cross-provider launcher preference

- Made `opusxm` the normal `x` choice for new directories while retaining native Claude and Fable lanes as explicit first-party fallbacks. `claudexm` remains the Sol-main alternative and now exposes a session-scoped `sonnet-worker` on Claude Sonnet 5; `opusxm` retains its session-scoped `sol-worker`.
- Added a versioned `routing=cross-provider-v1` launcher-state contract shared by `ccx` and `cc-handoff`. One-time migration maps prior native/Opus/Fable choices to `opusxm`, maps Sol-main choices to `claudexm`, preserves permission mode, creates a private backup, and writes atomically. A native lane selected after rollout remains a deliberate versioned choice.
- Replaced the old Fable-only bounded-handoff migration with generic exact-session model checks. JSONL inspection ignores sidechain workers and internal `<synthetic>` records; compatible sessions resume directly, while validated mismatches use Claude Code's full-history `--fork-session` path and record source-to-fork receipts when pconv can identify the new UUID.
- A loopback-only request-capture fixture verified that Claude Code 2.1.251 sends the selected target model on a fork, creates a new UUID, and leaves the source transcript byte-identical. No provider inference request or billed model call was made.

## Stable supervised entry point

- Added `profiles/bin/claude-cross-provider`, a small executable that enters the normal interactive Bash environment, verifies `opusxm` is available, forwards argv exactly, and delegates to the canonical launcher rather than duplicating provider preflight or containment logic.
- Updated the root installer to place the wrapper at `~/.local/bin/claude-cross-provider` and to print the required source order: `claude-code-helpers.sh` before `agent-launcher.sh`. The installer still does not rewrite shell startup files.
- Migrated active Portagenty Claude Code session commands from plain `claude` to the stable wrapper while preserving existing resume and permission flags. External workspace configs were copied to a private scratch backup before exact edits, and `pa <workspace> list` validated every changed TOML without launching sessions.

## Verification incident

- A final live-wrapper probe attempted to shadow `claude-contained` by prepending a temporary executable to `PATH`, but the child interactive `.bashrc` reordered `PATH` and resolved the real launcher. The probe created one disposable Opus session and one billed response instead of remaining inference-free. No existing transcript was resumed or modified, and no worker/delegation ran. The correct test boundary remains the controlled temporary `HOME`/`.bashrc` fixture plus an inside-child `command -v` assertion before any launch; never assume a parent `PATH` prefix survives `bash -ic`.
