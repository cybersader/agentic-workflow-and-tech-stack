## Fable delegate-first orchestration

- Made actual top-level Fable sessions delegate-first through the always-loaded global
  policy rather than relying on a skill to fire probabilistically. Fable retains contract
  freezing, sequencing, approvals, conflict resolution, synthesis, and final
  communication; substantive execution goes to bounded leaf workers.
- Recast model selection around task shapes—search/research, implementation, ecosystem
  work, debugging, architecture, verification, mechanical work, and closeout—with quota
  pressure as the cost axis. Opus is a valid heavy worker; Fable workers remain separately
  justified and approved exceptions.
- Added one shared Fable-main launcher rider and composed it with every named Fable lane.
  Lane-specific provider defaults, guard locks, and refill-pool facts remain authoritative;
  the rider changes orchestration posture rather than becoming a semantic model router.
- Clarified the architectural role boundary: top-level sessions and commands may
  orchestrate, while delegated workers are terminal leaves that return compressed
  evidence and never recursively delegate.
- Made the policy rebuildable: the root installer now publishes the canonical global
  `CLAUDE.md` and runtime skills, and the rebuild guide points at the real installer rather
  than a stale kernel-copy path.

## Project adapters

## Mobile agent access knowledge ops

- Replaced the single-client mental model with a surface decision guide: Termux or
  ConnectBot over SSH, Mosh as a separate roaming transport, Termius as a proprietary
  Mosh client, official Claude Code Remote Control, T3 Code as a local web control plane,
  tailnet-constrained remote desktop, and read-only tailnet browser output.
- Corrected the earlier omission of T3 Code. Its official architecture is a local server
  that owns provider CLIs, terminals, Git, and filesystem work while authenticated web,
  desktop, and mobile clients connect over WebSocket. Its remote guide directly supports
  Tailnet endpoints, one-time pairing, revocation, and opt-in Tailscale Serve HTTPS.
- Kept adoption gates explicit: no Remote Control, T3 server/listener, Tailscale Serve
  mapping, Mosh server/UDP rule, remote-desktop path, or mobile-client installation was
  enabled as a side effect of documenting the options.
- Reframed Termux as the current baseline and durable repair shell rather than the
  permanent default. Clipboard, battery, roaming, trust boundary, and long-output UX are
  separate evaluation axes.

## Plainspoken writing policy

- Added a lean global voice contract for direct, plain, specific answers without loading a
  full style checklist on every turn. Precise technical terms and useful punctuation remain
  valid; the rule targets canned framing, inflated claims, filler, and generic conclusions.
- Added `plainspoken-rewrite` as an explicit-only, read-only skill. It can rewrite supplied
  text or one named file into the response while preserving facts, certainty, quotations,
  citations, link targets, code, and Markdown structure. It never edits the source file and
  makes no AI-detector claim.
- Reworked `skill-patterns` around invocation mode, input/output and side-effect contracts,

## Portagenty supervision corrections and resource incident

- Traced a first-launch UUID failure to the outer TUI coordinator retaining a legacy
  workspace clone after the inner app had written and reloaded a stable UUID. Portagenty now
  hands the final workspace state back with the launch outcome, uses it for supervised
  dispatch and setup-failure resume, and gives a non-destructive upgrade message.
- The missing supervised live counts were not another state bug: the installed release
  binary predated the already-committed exact-receipt live-count implementation. The current
  release was rebuilt, so new picker processes now include exactly reconciled private
  supervised targets; existing manifests, receipts, units, and sessions required no repair.
- An initial uncontained Rust test pushed an already memory-heavy workstation into a
  swap/reclaim and disk-I/O cascade. The run exited without manual process termination, but
  it demonstrated that ordinary child builds can escape the intended supervision boundary.
  Subsequent Rust verification used one Cargo job in a transient user-systemd service with
  a 2 GiB `MemoryHigh`, 3 GiB `MemoryMax`, 512 MiB swap cap, reduced CPU/I/O weight, and a
  128-task limit. Peak memory stayed near 2 GiB with negligible swap and no pressure spike.
- Rustfmt, the UUID handoff regression, both supervised live-count regressions, and the
  release build passed in that bounded service. Full-suite and clippy reruns were skipped
  after the incident rather than spending more memory merely for ceremony.

## Portagenty and Claude containment integration

- Live inspection showed that Portagenty v1 receipts proved the transient multiplexer
  service and private target, while `claude-contained` moved the actual Claude root into
  a sibling scope. Portagenty therefore displayed resource ownership over a cgroup that
  held only the Zellij/tmux server and shell.
- Updated the watchdog wrapper to reuse an already-contained Claude leaf only after
  validating its kernel CPU, memory, swap, and oomd controls. Ordinary launches still
  create the standard bounded scope; malformed or weaker contained leaves fail closed.
  The watchdog bundle was verified through `build-contained` and installed with
  `--no-restart`, leaving all active Claude process IDs unchanged at deployment time.
- Portagenty now places explicit `kind = "claude-code"` sessions beneath
  `claude-code.slice` with 3 GiB high, 5 GiB hard memory, 512 MiB swap, 800% CPU, and
  1200-task defaults. Generic sessions do not inherit Claude policy. v2 receipts bind the
  exact unit, private multiplexer target, workload marker, PID/start time, resource
  properties, and a bounded all-thread descendant walk.
- tmux 3.7 creates `tmux-spawn-*.scope` units for panes by default. Private supervised
  tmux servers now start without the user-bus/runtime variables needed for that server-
  side scope creation, while the exact pane receives the restored values. Real synthetic
  tmux and Zellij systemd tests proved that the fake Claude root and descendants remained
  in the intended bounded service cgroup.
- Legacy v1 bindings remain exact-target attach-only and require normal exit/relaunch;
  they are never automatically stopped or migrated. Pending launches participate in
  preflight and block fallback until signal-free cleanup proves the creator, unit, target,
  and marker all absent. Split containment disables whole-workload control claims.
- Verification passed under sequential `build-contained` runs: Rust formatting, check,
  Clippy, 499 ordinary tests, release build, both ignored synthetic systemd end-to-end
  tests, the 13-page documentation build, whitespace checks, and sensitive-data plus
  prohibited-attribution scans. No pressure/OOM workload was used. Failed development
  probes left four dead runtime markers; their recorded PIDs were confirmed absent before
  those exact synthetic files were removed.
