## Global quota-recovery skill and CLAUDE.md rule-4 line

- What: added a global skill `.claude/skills/cliproxy-quota-recovery/SKILL.md` and appended one sentence to rule 4 ("Stop on quota, authentication, or routing failures") in `profiles/claude-global/CLAUDE.md`. No new rule number, no new section, nothing else in that file changed.
- Why: the 2026-09-08 work shipped the classifier, the `quota-unavailable` state, and the `cliproxy-reset-quota` helper, but left the *agent-facing* recognition and response undocumented. The distinctive `All credentials for model … are cooling down via provider codex (last error: usage_limit_reached …)` 429 reads like an upstream answer and is actually CLIProxyAPI's own in-memory circuit breaker refusing locally. Without a named home for that fact, the next session re-derives it under quota pressure — or retries.
- Layering: the always-loaded rule-4 sentence is the must-fire trigger (recognize the wording, stop, hand off the command); the skill is the reference the agent reads once that fires. Same split `local-search` uses, per `proactive-patterns` § Firing Reliability — a skill is never the trigger for must-fire behavior.
- Decision — the agent never runs the reset. `cliproxy-reset-quota` / `--reset-quota codex` clears only the *local* breaker; if the provider-side limit has not actually reset, the next request is a real one that re-trips it. An agent cannot verify the upstream state, so an agent-run reset is structurally a retry, and a retry an agent can repeat is a retry loop. The 2026-09-08 open item is the receipt: the proxy log shows hundreds-to-thousands of `429`s per hour on 2026-09-07/08 hammering an already-tripped breaker. The skill therefore assigns the reset to the human runbook only, and the shell helper keeps its interactive confirm and its single re-check.
- Skill body also covers: the three surfaces of the same state (preflight exit 25 with `Choose [r/c/a]`, the in-session 429, proxy log bursts); proxy-local vs. genuine upstream wording; the `HTTP 404` → `cliproxy-restart` fallback and its `save-cooldown-status: false` precondition; the transient-throttle case that keeps the "Launch anyway?" bypass; the don't-list (no re-login, no `disable-cooling`, no auth-file edits, no scripted reset); and the ≥ v7.2.155 `resets_at` upgrade note.
- Placement: `.claude/skills/` is the canonical home for skills that ship globally — `install.sh --claude` copies every `.claude/skills/<name>/` subdirectory to `~/.claude/skills/`. `profiles/claude-global/skills/` was checked and rejected: it holds only `deep-research`, hardcoded in `install-agent-budget.sh` as part of the guard bundle. Not mirrored into `01-kernel/skills/` (the public-site subset) because this is environment-specific operational content, same call as `local-search`.
- Sync step for `~/.claude` (not run here): `bash install.sh --claude` installs both the global `CLAUDE.md` and the skills tree in one pass.
- No inventory entry added: the repo keeps no static list of global skills. `profiles/README.md` is bashrc/keybinding profiles, `AGENTS.md` covers agents, `01-kernel/skills/index.md` autogenerates its sidebar from the published kernel subset, and project `CLAUDE.md` points at `ls .claude/skills/` rather than a table. `00-meta/skills-audit.md` is a dated 2026-04-17 audit, not a live inventory.
