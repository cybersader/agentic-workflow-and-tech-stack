## Sandboxed computer use, wave 1

- **Shape:** one model-budget workflow (`cu-sandbox-improve-wave1-sol`), hard cap 7, all GPT-6.1 Sol per the owner's request.
  - Scout (3 in parallel): CLI build, accessibility research, remote-approval research.
  - Then the accessibility build, a fresh-context adversarial review, the fix, and a recheck.
  - A first mixed-model version was cancelled before it changed anything, then rebuilt as all-Sol and re-approved.
  - Result: 7/7 agents, no errors.
- **Accessibility:** the empty tree came from a hard-coded stub in the in-image `computer_server` Linux handler, not from AT-SPI.
  - An optional offline-built image adds a bounded read-only AT-SPI reader (Python 3.10 + the already-installed `python3-dbus`, no new packages). It swaps only the stub, so the five-tool MCP is unchanged.
  - Proof: 117 real nodes, including terminal text and GTK widgets; MCP typing appears in the tree; the result survives recreation; 23/23 `verify` checks pass.
- **`cu-sandbox` CLI:** build/up/down/reset/verify/mcp-config/status, stdlib only.
  - The review found two medium issues, both fixed and rechecked:
    - The generated MCP launch didn't re-verify containment. It now gates on a host check bound to the immutable container ID.
    - Interrupted startup didn't clean up. It now does.
  - 29 unit tests pass, and 12 reader tests.
  - The orchestrator reran both suites and confirmed the container is stopped with no listeners.
- **Remote approval research:** keep it simple.
  - Tailscale SSH into the same multiplexer pane handles nonces; the controller's terminal mode handles grants.
  - Mosh is comfort, not security.
  - A future tailnet-only WebAuthn approval inbox is the GUI path, and only meaningful with an isolated authority.
  - Crumb: `zz-research/2026-10-01-remote-approval-and-gui-workspaces.md`.
- **Docs:** the plan doc gained "Accessibility fix" and "Sandbox CLI" sections, and its open questions were updated.
- **Still open:**
  - The guest-session permission kind. No owner session exists; the desktop-bridge consumer prefers a separate kind, bound to the verified container ID.
  - Whether to promote `cu-sandbox` into the repo as a profile.
