## GPT-6.1 Sol rollout

- OpenAI released GPT-6.1 Sol (`gpt-6.1-sol`). Both the local CLIProxyAPI catalog and OpenRouter's public catalog (`openai/gpt-6.1-sol`) listed it, at the same OpenRouter price as 6 Sol ($2/M input, $10/M output). There is no 6.1 Luna or Astra, so those stay on GPT-6.
- **Route proof:** with the human's approval, one minimal Messages-API request through the local proxy returned HTTP 200 from exactly `gpt-6.1-sol` (309 input / 5 output tokens). The OpenRouter alias was not inference-verified; it is catalog-listed only.
- **Same shape as the 2026-09-23 rollout:**
  - Every Sol-main lane, every Sol-locked lane's worker default and guard lock, and every session-scoped `sol-worker` now use `gpt-6.1-sol`. The locked-lane Sol catalog gate moved with it; flexible lanes still carry no Sol gate.
  - `ccx` treats `gpt-6.1-sol` as a distinct resume identity, so older-Sol sessions fork on resume.
  - Guard, policy, embedded dispatcher, and installer validation add `gpt-6.1-sol` to the local-proxy route and weekly OpenAI/Codex pool (not premium). `sol-worker` maps to it. `gpt-6-sol` and `gpt-5.6-sol` remain admitted as explicit legacy models. The dispatch-block pin was updated.
  - `sol-or-high` now maps to `openai/gpt-6.1-sol` in the repo manifest and the live proxy config (prior config backed up privately).
- **Verification:** launcher 65, model-lock 55, Fable policy 17, guard 189, portable allowance 77, installer 72, root installer 3, OpenRouter 19, dispatcher runtime 17 — all pass; launcher, model-lock, guard, Fable policy, and dispatcher suites were re-run independently by the orchestrator. Guard reinstalled without activation flags; installed guard matches source. One Sol worker implemented against a frozen contract; the orchestrator reviewed the diff.
- **Installed-rules drift found:** the installed global `CLAUDE.md` carries two communication rules (inverted funnel, stopping as a funnel question) that the canonical repo copy lacks. The installed copy was patched in place for the model-name change rather than overwritten, so those rules were preserved. Backporting them to the canonical copy is still open.
- Running sessions keep the model they launched with; relaunch to pick up 6.1.

## Claude Sonnet 5.5 rollout

- Anthropic released Claude Sonnet 5.5 (`claude-sonnet-5-5`). OpenRouter lists `anthropic/claude-sonnet-5.5` at the same price as Sonnet 5.
- **Route proof:** with the human's approval, one minimal Messages-API request through the local proxy returned HTTP 200 from exactly `claude-sonnet-5-5` (143 input / 4 output tokens, Anthropic 5h pool).
- **Changes (same shape as the Sol rollout above):**
  - Every session-scoped `sonnet-worker` definition now uses `claude-sonnet-5-5`.
  - The `ccx` native preset key `sonnet5` is kept for muscle memory but now launches Sonnet 5.5.
  - `ccx` treats `claude-sonnet-5-5` as a distinct resume identity, so Sonnet 5 sessions fork on resume.
  - Guard, policy, embedded dispatcher, and installer validation add `claude-sonnet-5-5` to the Anthropic 5h pool, and `sonnet-worker` maps to it. `claude-sonnet-5` stays admitted as an explicit legacy model. The dispatch-block pin was updated.
- **Intentionally unchanged:** the OpenRouter manifest (it has no Sonnet alias), both global rule files (neither names a versioned Sonnet default), and the pinned proxy patches.
- **Verification:** 520 tests, all passing: launcher 65, model-lock 58, Fable policy 17, guard 191, portable allowance 77, installer 72, root installer 3, OpenRouter 19, dispatcher runtime 18. The orchestrator re-ran the guard, model-lock, launcher, and dispatcher suites independently. The guard was reinstalled without activation flags, and the installed guard matches source.
- Running sessions keep their launch model. Relaunch to pick up both GPT-6.1 Sol and Sonnet 5.5.
