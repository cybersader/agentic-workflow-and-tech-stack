## Intuitive mixed-provider recovery

- Observed `fablexm` abort before session creation when Codex was quota-blocked even though the Fable main route remained healthy. The quota menu's `c` label implied a launcher action but only printed native commands and stopped, and the later `ccx` receipt step misleadingly said the fork completed despite no new UUID.
- Separated authentication repair from quota recovery. Missing, expired, or rejected credentials retain the ordinary login flow; an all-account quota state now explicitly offers signing in with a **different account that has available quota**. The hard-gate menu also offers selective stale-cooldown reset, prints native Claude alternatives without pretending to switch, or aborts by default. Login and reset each receive one bounded recheck with no automatic retries.
- Made flexible mixed-provider lanes hard-gate only the provider used by their main model. `claudexm` and `astraxm` require Codex but can continue without Claude-backed workers; `fablexm` and `opusxm` require Claude but can continue without Codex-backed workers. A degraded continuation appends a runtime rider naming the unavailable workers and forbidding their selection until provider health recovers. Pinned worker contracts such as `fablex` and `opusx` remain hard two-provider lanes.
- Corrected fork receipts to consider the nested launch return code and the presence of a new UUID. A cancelled or failed preflight with no new UUID now says no session was created; a real fork still receives a private source-to-fork receipt.
- Verification passed: 60 CLIProxy launcher tests, 38 launcher model-lock/fork tests, 15 Fable delegation-policy tests, Bash syntax, 246-file frontmatter validation, and scoped whitespace checks. The suites use fixture checkers, fake OAuth commands, PTYs, and fake pconv output only. No live OAuth flow was opened, no live proxy cooldown was reset, and no billable model request was sent.
- Notified the only other active local Claude session to exit and relaunch after the repaired launcher source is available so its startup-sourced functions and worker rider refresh; running sessions retain their old process environment until restart.

## Tailscale SSH browser-check alignment

- Corrected a diagnosis that treated a Tailscale SSH authorization delay as an `sshd`/daemon failure. The node was online, `tailscale ping` succeeded directly, and the port-22 intercept answered; the actual response was Tailscale's expected `additional check` policy challenge.
- Verified the intended recovery end to end: kept one `tailscale ssh <linux-user>@<host> 'id && hostname'` process alive, surfaced its browser URL, and let the same process resume after human reauthentication. It returned the expected Linux identity and hostname without restarting `sshd`, restarting `tailscaled`, or using VNC/serial access.
- Promoted the correction into the always-loaded global policy, portable `AGENTS.md`, and the cross-device pattern/index: Tailscale SSH is a `tailscaled` path, the admin-console owner label is not the target Linux username, browser-check URLs should be clickable, and service restarts require evidence from status/ping rather than inference from an auth prompt. Reinstalled both global Claude policy and portable agent guidance so future sessions and non-Claude coding tools receive the same rule.
