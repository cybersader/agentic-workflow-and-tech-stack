## Local-first Claude UI and terminal copy ergonomics

- Added a must-fire command-presentation rule to the canonical global Claude instructions: prefer one short command, turn multiline or multi-step shell work into a script plus one invocation, suggest `! <command>` for interactive commands, and never depend on copying a wrapped command block through a multiplexer. No RustDesk, Tailscale, KDE, portal, watcher, listening-port, Remote Control, Zellij web-server, or GUI installation change was made.
- Kept Portagenty's boundary narrow: workspace discovery, launch configuration, and session attachment remain its durable role. ## Agent control-plane research

- Added a bounded near-term roadmap track for three related evaluations: Happier as a phone-native local-session surface, Portagenty as the address resolver beneath a real inter-agent transport, and Fedora/Linux agent workload supervision. Each item has an exit criterion and explicitly remains evaluation rather than adoption.
- Verified Portagenty's present boundary from its local source. A workspace UUID plus exact declared session name is a useful stable address, but Portagenty currently offers registry, resolution, multiplexer attach/takeover, and lifecycle control—not addressed message delivery, queueing, acknowledgements, idempotency, or input injection.
- Recorded a transport-neutral model based on `SessionAddress`, capability-bearing resolution, typed envelopes, adapter-specific delivery, and receipts. The durable filesystem inbox remains the baseline candidate; clipboard automation and a one-off `pa paste` command were rejected as substitutes for the abstraction.
- Added [Agent Resource Supervision and Control Plane](../zz-research/2026-08-21-agent-resource-supervision-and-control-plane.md) for the recurring Fedora failure shape where multiple agent workloads make the workstation progressively slow without a clean crash. The research separates logical identity, cgroup/process attribution, pressure metrics, and a confirmation-gated narrow-to-wide termination ladder before choosing a GUI.
- Existing tools cover only pieces of that requirement: process GUIs provide per-process visibility, while systemd cgroup tools provide authoritative workload aggregation. No custom GUI, daemon, service, listener, package install, process signal, or unrelated containment/watchdog change was made.
- Captured an open known issue that an earlier private agentic-workflow update did not appear in the expected public mirror. The note separates source commit, workflow trigger, extractor allowlist/frontmatter, leak gate, mirror push, and site deployment as diagnostic boundaries; no publication configuration or remote repository was changed in this pass.
