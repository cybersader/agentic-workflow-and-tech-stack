## Workflow authorization and model-lane boundaries

- Strengthened the `agent-guard` approval card into an explicit stop/paste/wait protocol: a blocked Workflow now tells the assistant not to use `AskUserQuestion` or retry, and to give the human the exact standalone `approve-workflow` command in a normal response. Identical premature retries reuse the live nonce instead of creating a moving approval target; pending requests now share the configured ten-minute expiry.
- Added a guard-owned `AGENT_GUARD_SUBAGENT_MODEL_LOCK` to pinned launchers. This became necessary after confirming that explicit Workflow `agent(..., {model})` options can override `CLAUDE_CODE_SUBAGENT_MODEL` and silently route workers to a different provider lane.
- Extended registered Workflow metadata with `subagentModelPolicy`. Locked sessions admit only hash-attested `inherit-launcher` workflows; opaque named or unregistered workflows cannot receive one-shot approval on a locked lane because their internal model routing is not enforceable from the outer hook.
- Made the registered bounded-parallel and deep-research workflows model-neutral. Bounded-parallel rejects per-task model fields before launching workers; deep-research inherits the selected launcher model and fails fast on authentication, quota, and provider-routing errors instead of scheduling later phases against the same broken lane.
- Updated global/project instructions, launcher descriptions, and the scaffold delegation skill so the prompt layer matches the deterministic hook behavior.
- Added focused guard, installer, launcher, bounded-parallel, and deep-research regression coverage. Validation passed: 32 Python tests, both JavaScript workflow suites, shell syntax checks, and Python compilation.
- Installed the updated guard, policy, manifest, and registered workflows into the active Claude Code profile. Fresh sessions are required to inherit the new launcher model-lock environment and refreshed global instructions.

## Notes / observations

- `CLAUDE_CODE_SUBAGENT_MODEL` remains useful as the harness default but is not, by itself, a security or quota boundary for Workflow-internal workers.
- Count authorization and model authorization are separate questions: a human-approved agent ceiling cannot attest an opaque Workflow's provider routing.
