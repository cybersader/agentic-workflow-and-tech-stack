## Claude Fable 5.1 launcher migration

- Retargeted the native Fable launcher family to Anthropic's exact `claude-fable-5-1` model ID while keeping the established command and alias names.
- Kept the bare `fable` worker-tier alias, introduced `fable51` as the canonical `ccx` main-model key, and retained compatibility for existing launcher-state files that record `mainmodel=fable5`.
- Paused `fablex` and `fablexm` fail-closed because CLIProxyAPI does not yet advertise the Fable 5.1 OAuth route. The commands remain discoverable but refuse before login, proxy restart, or model launch rather than silently using Fable 5 or surfacing `no auth available`.
- Preserved native 1M context without a `[1m]` suffix and retained the existing $10/$50 input/output pricing description.
- Hardened every native Fable launcher and the generic `ccx` native branch to clear inherited `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN` before invoking `claude-contained`. This keeps `fableo`, `fablef`, `fablem`, and `ccx`-selected Fable 5.1 on first-party Anthropic authentication even when launched from a shell that was itself started through CLIProxyAPI.
- Closed the resumed-session migration gap exposed by TeachingStack: Claude Code retained the transcript's recorded Fable 5 model even when `ccx` supplied the Fable 5.1 flag. `ccx` now detects that exact mismatch for pconv-resolved sessions and automatically converts the normal resume into a bounded handoff, launching a genuinely fresh Fable 5.1 transcript while leaving the source untouched.
