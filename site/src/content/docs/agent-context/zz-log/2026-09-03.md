## Portagenty split-session lifecycle

- Traced repeated inability to stop several supervised Zellij shell sessions to the same interaction: a shell-owned Portagenty service launched Claude through `claude-contained`, which intentionally moved Claude into a separately bounded `claude-code.slice` scope. Portagenty correctly classified the resulting tree as split containment, but its TUI then blocked every stop action even though the exact private multiplexer target and Portagenty service remained verifiable.
- Changed the control boundary rather than weakening ownership proof: split rows can now confirm a graceful stop of the exact private target followed by a non-force stop of the verified Portagenty service. External scopes are never signalled, may remain active, and still prevent whole-workload metrics and force-kill. Current v2 receipts that predate the complete automatic limit policy receive the same non-force stop path, while legacy v1 receipts remain attach-only.
- Hardened the relaxed non-force path by reading back and requiring `ExitType=cgroup`, `KillMode=control-group`, and `SendSIGKILL=no` on current v2 services. Force-kill remains restricted to complete owned-and-verified containment.
- Cleared two proven-stale session receipts through Portagenty's signal-free cleanup command. No live process, service, multiplexer target, or Claude conversation was signalled during cleanup.
- Verified the change with the full Rust suite, Clippy with warnings denied, both live synthetic systemd/tmux and systemd/Zellij supervision fixtures, the documentation build, and the installed release binary. Existing live sessions were left running for the operator to close deliberately after reopening Portagenty.

## Workspace-wide split-session stop correction

- A follow-up usage report exposed that the first repair covered row-scoped `x` and explicit CLI stop but left the global picker’s workspace-wide `X` action intentionally skipping split-containment sessions. That conservative exception preserved safety but failed the actual one-action workspace shutdown workflow.
- Extended workspace-wide stop to preview and include owned, split-containment, and current v2 incomplete-policy receipts through the same exact-target/non-force service path. Legacy v1, stale, pending, ambiguous, and otherwise unsafe states remain skipped; external descendant scopes are never signalled and force escalation remains unavailable.
- Added pure classification and confirmation-copy regression tests, reran the complete 467-test Rust suite and Clippy with warnings denied, rebuilt the documentation, and installed the verified release binary without stopping any live user session.

## CLIProxyAPI single-credential recovery repair

- Diagnosed repeated `503 auth_unavailable` loops as local scheduler rejection while the only Codex credential was unavailable: the failed requests returned in 1–5 ms without reaching upstream, and Claude Code's default 10-attempt transport retry held sessions in the same unavailable lane.
- Upgraded the loopback proxy from CLIProxyAPI `v7.2.125` to verified release `v7.2.149`, preserving private rollback copies of the prior binary and configuration. The managed transient user service remains isolated in `cliproxyapi-managed.service`; both OAuth credential files stayed byte-identical across the authorized restart.
- Configured `transient-error-cooldown-seconds: -1` for the single-credential deployment so recoverable `408`/`5xx` failures do not turn into a no-candidate cooldown window. Authentication and quota failures retain their normal hard handling.
- Bounded every active proxy-backed Claude Code launcher to two transport retries through an overridable `CLIPROXY_MAX_RETRIES` default, added focused launcher coverage, and documented the operational contract. Verification used only version, management, configuration, placement, syntax, and test checks; no inference request or delegated worker was launched.
